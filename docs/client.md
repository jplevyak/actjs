# @jplevyak/actjs/client

The framework-agnostic TypeScript client. One `Client` multiplexes
every call and subscription over a single WebSocket, manages
reconnect + backoff, applies subscription updates locally, runs
optimistic mutations, and queues offline writes.

The React/Svelte bindings (Phase 6.3) are thin wrappers over this
surface.

## Install

The SDK is exported from the `@jplevyak/actjs` package as `@jplevyak/actjs/client`:

```ts
import { Client } from '@jplevyak/actjs/client';
```

The package ships ESM only; consumers transpile to whatever shape
they need (Vite, esbuild, Rollup, tsc, etc.).

In Node, supply the `ws` package as the WebSocket constructor:

```ts
import WS from 'ws';
import { Client } from '@jplevyak/actjs/client';

const client = new Client({ url: 'http://localhost:3000', wsCtor: WS });
```

In browsers the global `WebSocket` is picked up automatically.

## Quick start

```ts
import { Client } from '@jplevyak/actjs/client';
// Generated by `actctl codegen`.
import type { Classes } from './client-types';
import { MANIFEST_SHA } from './client-types';
import { reducers } from './client-types/index.runtime.js';

const client = new Client({
  url: 'https://api.example.com',
  token: localStorage.getItem('token') ?? undefined,
  pin: MANIFEST_SHA,
  reducers,
});

const cart = client.actor<Classes['Cart']['handlers'], Classes['Cart']['state']>('Cart', cartId);

await cart.call.addItem({ sku: 'X', qty: 2 });
const total = await cart.call.total();
const unsub = await cart.subscribe((state) => render(state));
```

`call.<method>` is duck-typed at runtime — the actual type
checking comes from the codegen'd `Classes` umbrella. A non-existent
method is a compile-time error before it can become a runtime
error.

## Constructor options

| Option             | Default            | Purpose                                                        |
| ------------------ | ------------------ | -------------------------------------------------------------- |
| `url`              | (required)         | Base URL of the server. WS endpoint is derived.                |
| `token`            | —                  | Bearer token; supplied to the auth hook.                       |
| `pin`              | `'latest'`         | Manifest sha sent as `X-Actjs-Manifest`.                       |
| `reducers`         | `{}`               | ES reducer map from `actctl codegen`.                          |
| `offlineQueue`     | `'memory'`         | `'memory'` / `'indexeddb'` / `'none'` / your own backend.      |
| `wsCtor`           | global `WebSocket` | Inject a WS constructor (Node uses `ws`).                      |
| `autoConnect`      | `true`             | Open the WS in the constructor.                                |
| `onWarning`        | —                  | Surface transport reconnects / deprecation hints.              |
| `onMutationFailed` | —                  | Fired when an offline call is dropped after permanent failure. |

## ActorHandle

`client.actor(className, id)` returns:

```ts
interface ActorHandle<Calls, State> {
  readonly class: string;
  readonly id: string;
  call: Calls; // typed proxy
  get: Calls; // alias for read-style intent
  subscribe(listener: (s: State) => void, opts?: SubscribeOptions): Promise<() => void>;
  optimistic(mutator: (draft: State) => void, opts?: CallOptions): Promise<void>;
}
```

- `call.<method>` returns the server response.
- `get.<method>` is the same proxy; the name documents read-only
  intent at the call site.
- `subscribe` returns an unsubscribe function. The listener fires
  for every snapshot, patch, event, and tombstone the actor
  produces — the SDK applies each notification before invoking
  listeners, so they always see consistent state.
- `optimistic(mutator)` runs the mutator against the current
  subscribed state via Immer, fires the server call, and reverts
  with the inverse patches if the server rejects.

## Manifest pin

The pin is sent on every REST call (`X-Actjs-Manifest`) and as a
query param on the WS connect URL. Three modes:

- **Build-time pin** — `pin: MANIFEST_SHA` from the codegen
  artifact. The build is locked to that schema.
- **Latest** — `pin: 'latest'` (the default). The SDK omits the
  header and the server resolves fresh on each request. Use in
  development; not recommended for production.
- **Custom** — pass an arbitrary sha. Useful for staged rollouts
  ("connect to the pin our staging frontend was built against").

You can change the pin at runtime via `client.setManifestPin(...)`;
already-open WS connections are not torn down — the pin change
applies to subsequent reconnects.

## Reconnect

The transport uses full-jitter exponential backoff:

```
delay = uniform(0, min(30_000ms, 250ms * 2^attempt))
```

On reconnect:

- Pending RPC requests are re-sent. `actor.call` is idempotent
  when the SDK supplies an Idempotency-Key (always); `actor.subscribe`
  re-issues fresh and the new `subscriptionId` is updated.
- The offline queue is drained in FIFO order.
- Subscriptions that were active before the drop are re-established.

`onWarning({ type: 'transport-reconnecting', attempt, delayMs })`
fires for every reconnect attempt so the app can show a connection
indicator.

## Offline queue

Mutations issued while the transport is down (or that fail with a
retryable error) can be persisted to a backend keyed by
`Idempotency-Key`. The default backend is `'memory'`; pass
`offlineQueue: 'indexeddb'` for durable persistence in browsers.

```ts
import { IndexedDbOfflineQueue } from '@jplevyak/actjs/client';
const queue = new IndexedDbOfflineQueue();
const client = new Client({ url, offlineQueue: queue });
```

Permanent failures (server returns a non-retryable problem-detail
code) call `onMutationFailed(call, err)` and drop the entry.
Retryable failures (`MailboxFull`, `SubscriberLimit`, network
blips) remain in the queue and replay on the next successful
connect.

## Optimistic updates

```ts
await cart.optimistic((draft) => {
  draft.items.push({ sku: 'X', qty: 2 });
});
```

Semantics:

- The mutator runs against the current subscribed state via Immer,
  producing the new state and the inverse patches.
- The new state is emitted to subscribers immediately.
- The matching server call (deduced by the SDK from the actor's
  most recent `call.*` invocation) runs in the background.
- On rejection, the inverse patches are applied to the _current_
  state (not the pre-mutation state), so concurrent updates don't
  get clobbered.
- On success, the server's snapshot eventually reconciles. If
  it diverges from the optimistic prediction, the server wins by
  design.

ES actors are not yet supported by `optimistic()`. ES requires
predicting the _events_ the server will emit; that lands in a
follow-up. Use `call` directly for ES.

## Warnings

The `onWarning` callback surfaces:

- `transport-reconnecting` — connection dropped; a reconnect is
  scheduled.
- `manifest-deprecated` — the server returned a `Warning` header
  or a deprecation notification (`VersionDeprecated`). Tells the
  app the pinned manifest references a deprecated version; consider
  rebuilding.

## Wire-level errors

Server errors arrive as `RpcError`:

```ts
import { RpcError } from '@jplevyak/actjs/client';

try {
  await cart.call.addItem({ sku: 'X', qty: 2 });
} catch (err) {
  if (err instanceof RpcError) {
    console.log(err.code, err.frameworkCode, err.data);
  }
}
```

- `err.code` is the JSON-RPC integer code.
- `err.frameworkCode` is the actjs error string (`SubscriberLimit`,
  `MailboxFull`, `Forbidden`, `Unauthorized`, …).
- `err.data` is the raw `data` payload (often the problem-detail
  JSON).

## Caveats

- **Pinned manifest in stale tabs.** A browser tab built against an
  old pin keeps sending that pin even after a deploy. The server
  honors the pin (manifests are immutable), but new class versions
  aren't picked up until the tab is reloaded. Use a service-worker
  cache strategy that invalidates on `MANIFEST_SHA` change if you
  need faster turnover.
- **WS upgrade auth.** Browsers can't set `Authorization` headers
  on `WebSocket` opens. The SDK passes `token` as a query param;
  ensure your `auth` hook handles that, or run cookie-based auth
  for SSE/WS in browsers.
