# Framework bindings

Thin React and Svelte adapters over [`@actjs/client`](./client.md).
The bindings give app code a native-feeling primitive — hooks for
React, stores for Svelte — without duplicating the SDK's call,
subscription, or optimistic logic.

The bindings are exported as:

| Entry                   | Imports                                                                      |
| ----------------------- | ---------------------------------------------------------------------------- |
| `actjs/bindings`        | Shared `ActorStore`, `selectStore`, `getActorStore`, `releaseActorStore`.    |
| `actjs/bindings/react`  | `configureReact`, `useActor`, `useActorValue`, `useActorCall`, `fetchActor`. |
| `actjs/bindings/svelte` | `actor`, `actorValue`, `loadActor`.                                          |

React and Svelte are **peer dependencies** — actjs declares the
adapter surface but doesn't pull either framework into your bundle.

## React

```tsx
import React, { Suspense } from 'react';
import { Client } from 'actjs/client';
import { configureReact, useActor, useActorCall } from 'actjs/bindings/react';
// Generated by `actctl codegen`:
import type { Classes } from './client-types';

configureReact(React);

const client = new Client({ url: 'https://api.example.com' });

function CartView({ id }: { id: string }) {
  const state = useActor<Classes['Cart']['handlers'], Classes['Cart']['state']>(
    client,
    'Cart',
    id,
    { suspend: true },
  );
  const { call, pending, error } = useActorCall<
    Classes['Cart']['handlers'],
    Classes['Cart']['state']
  >(client, 'Cart', id);

  return (
    <div>
      <ul>
        {state.items.map((i) => (
          <li key={i.sku}>
            {i.sku} × {i.qty}
          </li>
        ))}
      </ul>
      <button disabled={pending} onClick={() => call.addItem({ sku: 'X', qty: 1 })}>
        Add
      </button>
      {error ? <p>Error: {String(error)}</p> : null}
    </div>
  );
}

export default function App({ id }: { id: string }) {
  return (
    <Suspense fallback={<p>Loading…</p>}>
      <CartView id={id} />
    </Suspense>
  );
}
```

### Why `configureReact(React)`?

The adapter doesn't `import React from 'react'`. Two reasons:

- The actjs package doesn't depend on React, so consumers without
  React see no React in their tree.
- Some apps load React via a CDN or a custom bundling chain (esbuild
  - import-maps); having actjs `import` React would create a second
    copy in the worst case.

Call `configureReact(React)` once at app startup, alongside
`createRoot`. The hooks then use whichever React instance you've
configured.

### Hooks

- `useActor(client, class, id, options?)` — current state; subscribes
  on mount, unsubscribes on unmount. `{ suspend: true }` throws the
  ready promise so the nearest Suspense boundary shows its fallback
  during the initial subscribe round-trip.
- `useActorValue(client, class, id, selector)` — same, but the
  selector is memoized; `Object.is` equality short-circuits
  re-renders.
- `useActorCall(client, class, id)` — returns `{ call, pending,
error, optimistic }`. Calls run inside `useTransition`, so React
  keeps the existing UI responsive while the mutation is pending.

### `fetchActor` for server components

```tsx
// app/cart/[id]/page.tsx (React Server Component)
import { Client } from 'actjs/client';
import { fetchActor } from 'actjs/bindings/react';

const client = new Client({ url: process.env.ACTJS_URL!, autoConnect: false });

export default async function Page({ params }: { params: { id: string } }) {
  const { snapshot } = await fetchActor<Classes['Cart']['state']>(client, 'Cart', params.id);
  return <CartView id={params.id} initial={snapshot} />;
}
```

The snapshot is fully serializable; pass it as a prop to the
hydrating client component and the first paint shows real data.

## Svelte

```svelte
<script lang="ts">
  import { Client } from 'actjs/client';
  import { actor } from 'actjs/bindings/svelte';
  import type { Classes } from '$lib/client-types';

  const client = new Client({ url: 'https://api.example.com' });
  export let id: string;

  const cart = actor<Classes['Cart']['handlers'], Classes['Cart']['state']>(
    client,
    'Cart',
    id,
  );
</script>

{#if $cart.loading}
  <p>Loading…</p>
{:else if $cart.error}
  <p>Error: {$cart.error}</p>
{:else}
  <ul>
    {#each $cart.state.items as item}
      <li>{item.sku} × {item.qty}</li>
    {/each}
  </ul>
  <button on:click={() => cart.call.addItem({ sku: 'X', qty: 1 })}>Add</button>
{/if}
```

The `actor(...)` store satisfies Svelte's readable-store contract
— `$cart` unwraps to `{ state, loading, error }`. Method calls go
through `cart.call.<method>(args)` exactly like the SDK's
ActorHandle.

### SvelteKit SSR

```ts
// +page.server.ts
import { loadActor } from 'actjs/bindings/svelte';
import { client } from '$lib/server/client';

export async function load({ params }) {
  return await loadActor(client, 'Cart', params.id);
}
```

The result is `{ snapshot, manifestSha }`. The client-side
`actor(...)` store starts from `loading: true` and replaces with
the live snapshot as soon as the WS subscribe resolves; if you want
to skip the loading flash, feed the SSR snapshot into the page's
initial state.

## Selectors

Both adapters expose a slice helper:

```ts
// React
const total = useActorValue(client, 'Cart', id, (s) => s.total);

// Svelte
const total = actorValue(client, 'Cart', id, (s) => s.total);
```

A selector that returns the same value (by `Object.is`) does not
trigger a re-render. For non-primitive slices, return a stable
identity (e.g. an Immer projection) so equality holds.

## Reference counting

`getActorStore(client, class, id)` is a reference-counted registry:
multiple hooks observing the same actor share one upstream WS
subscription. The last `releaseActorStore` tears down the upstream;
the next call creates a fresh store. This is the property React's
`useSyncExternalStore` and Svelte's `subscribe` contract both
depend on — they assume a stable identity across renders.

You normally don't call `getActorStore` directly; the React hooks
and Svelte stores wrap it.

## Caveats

- **React 19 RSC is still evolving.** The `fetchActor` helper works
  with the current spec; pin a React minor version and re-test
  on bumps. Server Action support is out of scope here.
- **Svelte 4 vs 5.** `subscribe(run)` is the same in both. Svelte 5
  apps can drop the `$` prefix and consume the store with `$state`
  derivations — see SvelteKit docs.
- **Bundle size.** The adapters are < 2 KiB min+gz each on their
  own; the dominant cost is `@actjs/client` and Immer. If you need
  budget tuning, import the framework-specific entry directly
  (`actjs/bindings/react`) so the other adapter tree-shakes out.
- **DOM tests.** The repo ships store-contract tests, not full
  mount tests. Apps embedding actjs typically run their own
  `@testing-library` setup, which the adapters work with directly.
