# Codegen

`actctl codegen` reads class TypeScript source from a published
actjs deployment and emits three artifacts the frontend SDK
consumes:

| File               | Purpose                                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------- |
| `index.d.ts`       | Per-class state type, ES event union, handler interface; a `Classes` umbrella; `MANIFEST_SHA` constant. |
| `manifest.json`    | Resolved version map + manifest sha + per-class source shas.                                            |
| `index.runtime.js` | ES reducers, byte-identical semantics to the server's `reduce`. Tree-shakeable.                         |

These commit to the consuming app's repo (typical layout
`client-types/`) and CI runs `actctl codegen --check` to ensure
they aren't stale.

## Usage

```bash
# Local source (a directory of `*.ts` files):
actctl codegen --source local:./classes --out ./client-types

# Server source (HTTP API + admin token):
actctl codegen \
  --source https://api.example.com \
  --target prod \
  --token $ADMIN_TOKEN \
  --out ./client-types

# CI check: exits 1 with a unified diff if regen is needed.
actctl codegen --source local:./classes --out ./client-types --check
```

### Flags

| Flag       | Meaning                                                         |
| ---------- | --------------------------------------------------------------- |
| `--source` | `local:<dir>` or `http(s)://<base-url>`. Required.              |
| `--out`    | Output directory. Default `./client-types`.                     |
| `--root`   | Repo root for the `.actctl/` cache. Default `--out`.            |
| `--target` | `dev` / `staging` / `prod` (HTTP source only). Default `prod`.  |
| `--token`  | Bearer token (HTTP source). Falls back to `$ACTJS_ADMIN_TOKEN`. |
| `--check`  | Diff mode; non-zero exit on drift.                              |
| `--force`  | Ignore the incremental cache.                                   |

## Output details

### `index.d.ts`

```ts
// generated by actctl codegen — do not edit
export const MANIFEST_SHA = 'b57a639b…' as const;

// Cart@1.2.0 (sha256: 18e187a12389…)
export type CartState = { items: { sku: string; qty: number }[] };
export interface CartHandlers {
  addItem(args: { sku: string; qty: number }): Promise<{ total: number }>;
  clear(args: Record<string, never>): Promise<void>;
}

// Ledger@2.0.0 (sha256: 718303e09349…)
export type LedgerState = { balance: number };
export type LedgerEvent = { type: 'credit'; amount: number } | { type: 'debit'; amount: number };
export interface LedgerHandlers {
  credit(args: { amount: number }): Promise<LedgerEvent[]>;
}

export interface Classes {
  Cart: { state: CartState; event: never; handlers: CartHandlers; eventSourced: false };
  Ledger: { state: LedgerState; event: LedgerEvent; handlers: LedgerHandlers; eventSourced: true };
}
export type ClassName = keyof Classes;
```

The SDK's typed `client.actor('Cart', id).call.addItem({ … })` is
checked against `Classes['Cart']['handlers']['addItem']`.

### `manifest.json`

```json
{
  "sha256": "b57a639b74f10befb3231df58d3d25723519408cd65b2cebe60f08242cd926f4",
  "resolved": { "Cart": "1.2.0", "Ledger": "2.0.0" },
  "sources": { "Cart": "18e187a1…", "Ledger": "718303e0…" }
}
```

`sha256` is the canonical-JSON sha of the `{ name → version }` map.
The server computes the same sha on every pin request (see
`src/types/manifest.ts`), so the embedded value sent as
`X-Actjs-Manifest` always matches what the registry expects.

### `index.runtime.js`

```js
export const reducers = Object.freeze({
  Ledger: (state, event) => {
    if (event.type === 'credit') return { balance: state.balance + event.amount };
    return { balance: state.balance - event.amount };
  },
});

export function applyEvent(className, state, event) {
  const r = reducers[className];
  if (!r) throw new Error(`no reducer for ${className}`);
  return r(state, event);
}
```

ES reducers are transpiled from the server's TS source via
`ts.transpileModule`, so the client-side fold is guaranteed to be
byte-identical to the server's. Only `reduce` methods get
transpiled — other class methods aren't part of the client
contract.

## Supported authoring shapes

The extractor reads syntactic types only (no type checker), so
classes must be written in a constrained subset:

```ts
// SWM:
class Cart extends actjs.Actor<{ items: Item[] }> {
  @handler('addItem')
  addItem(args: { sku: string; qty: number }): { total: number } { … }
}

// ES:
type LedgerEvent = { type: 'credit'; amount: number } | { type: 'debit'; amount: number };
class Ledger extends actjs.EventSourced<{ balance: number }, LedgerEvent> {
  reduce(state: { balance: number }, event: LedgerEvent): { balance: number } { … }
  @handler('credit')
  credit(args: { amount: number }): LedgerEvent[] { … }
}
```

### What works

- Inline object types as `<State>` / `<Event>` type arguments.
- Locally declared type aliases — they're inlined into the output.
- `@handler('name')` and `@handler()` (defaults to the method name).
- Concrete `Promise<T>` return types — peeled to `T`.

### What gets a warning

- Generic handlers (`<T>(args: T): T`) — emitted as `unknown`.
- Conditional / mapped types in handler signatures — emitted
  verbatim, may fail type-check on the consumer side.
- Handlers without an explicit return type — emitted as `unknown`.

### What is rejected

- Decorators / enums / namespaces inside `reduce` — `ts.transpileModule`
  may emit code that depends on `__decorate` helpers, which break
  the tree-shake guarantee. Use plain functions instead.

## Incremental builds

`actctl` keeps a JSON file at `<root>/.actctl/last-sha.json` with
the most recent manifest sha and per-class source shas. On the
next run, if every class's source hash matches the cache and the
output files exist, codegen exits in `skipped` status without
running the parser.

The cache is best-effort: deleting `.actctl/` always forces a full
regen.

## CI integration

```yaml
# .github/workflows/check.yml
- run: npm ci
- run: npx actctl codegen --source local:./classes --out ./client-types --check
```

`--check` exits with code `1` and prints a unified diff to stderr
when the committed output is stale, so a "regenerate the SDK"
task surfaces in the same PR that changed a handler signature.

## Programmatic use

```ts
import { run, localLoader } from '@jplevyak/actjs/codegen';

const result = await run({
  source: localLoader({ dir: './classes' }),
  outDir: './client-types',
  check: process.env.CI === 'true',
});
if (result.status === 'check-drift') {
  console.error(result.diff);
  process.exit(1);
}
```
